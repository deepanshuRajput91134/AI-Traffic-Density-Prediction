# Database Architecture — Smart City AI Traffic System

## Overview
The persistence layer utilizes **SQLite** for lightweight, zero-configuration local database operations, fully compatible with macOS, Linux, and Windows without requiring standalone database servers.

## Schema Entities

### 1. `traffic_records`
Stores every traffic density inference performed by the ML model.
* `id`: Auto-incrementing primary key.
* `timestamp`: UTC timestamp of the prediction event.
* `vehicle_count`: Count of observed vehicles in corridor.
* `average_speed`: Observed velocity in km/h.
* `road_capacity`: Baseline corridor vehicle capacity.
* `predicted_density`: ML classification (`Low`, `Medium`, `High`).
* `congestion_ratio`: Calculated capacity utilization percentage `(vehicle_count / road_capacity) * 100`.
* `source`: Data origin tag (`manual`, `simulation`, `vision`).

### 2. `route_records`
Logs pathfinding recommendations computed by the Dijkstra optimization engine.
* `id`: Primary key.
* `timestamp`: Calculation timestamp.
* `origin`: Starting node/intersection.
* `destination`: Destination node/intersection.
* `recommended_route`: Name of the optimal route selected.
* `travel_time`: Estimated trip duration in minutes.
* `route_score`: Composite multi-objective cost score.
* `traffic_density`: Dominant congestion state across the route corridor.
* `alternative_routes`: Serialized JSON array with details of 2 alternative candidate routes.
* `recommendation_reason`: Human-readable justification generated by the system.

### 3. `simulation_presets`
Pre-configured scenarios designed for deterministic demonstration during college project viva and review sessions.

## File Location
* Schema definition: `database/schema.sql`
* Database binary: `database/traffic_system.db` (created automatically on first backend launch)
